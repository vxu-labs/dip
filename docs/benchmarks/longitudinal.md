# Longitudinal quality experiment

The experiment is preregistered before scored model execution. Results are pending.

Four matched project pairs receive the same order-processing project, with varied policy constants. Each arm has nine fresh conversations: partial implementation, an actual requirement revision, a side task with a new future idea and a cancellation, an abrupt process interruption, two concurrent isolated Git worktree workers, integration, a second actual revision and a read-only audit. This schedules 72 model conversations.

The baseline may use ordinary Markdown plans and handoff notes. The treatment adds DIP 0.3.4 instructions, generated trusted Codex hooks and approved MCP tools with a private shared runtime. Neither arm uses a resident DIP recorder, shell profiles or native Git discovery. Worktrees protect product files in both arms.

Primary quality scoring uses 30 predetermined external functional cases per final project. Secondary measures include ten recovered policy fields, two deferred ideas, one cancelled idea, unsupported completion claims, false release-readiness claims, actual merge conflicts and audit compliance. Intermediate snapshots expose recovery and regressions; tokens and elapsed time are secondary. No evaluator feedback or result-dependent retries will be given to participants.

This is an accelerated synthetic project lifecycle with four paired repetitions in one domain. It is not a multi-day field study, a distributed-locking test, a statistical proof of general productivity or a benchmark of all possible code quality. Intentional interrupted turns may not report token usage.
