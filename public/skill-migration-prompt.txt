Organize the external agent skills on this computer into the DIP storage of each project. Work locally, in small reversible groups. This computer already has DIP installed.

1. Run `dip projects` and `dip skills sync --full` to find project roots, worktrees and skill sources. Read each project's agent instructions. Inspect who loads each skill, including application imports, build scripts, archive tooling and CI that reads files directly from Git. A skill loaded by an application's own internal agents stays in its existing application path. A skill used by an external agent to work on the application is a migration candidate. Keep user-global installations separate from project skills.

2. For each eligible project skill, move the entire bundle, including SKILL.md, invocation policy, scripts, references and assets, into `.dip/skills/<name>/` at the project root or within the skill's existing subdirectory scope. Use scoped storage when relative references depend on that directory. Keep the original native discovery entry under `.agents/skills/` for Codex or `.claude/skills/` for Claude Code as a relative directory link to the DIP bundle. Preserve names, scope and invocation policy. Keep provider-managed installs under their updater until you can verify its update behavior.

3. Save a rollback record before each group. Preserve existing edits and avoid destination collisions. After each group, compare file hashes, executable modes and relative references. Verify the skill in a fresh session of each host that is supposed to discover it, and check that an unrelated project does not see it. Check fresh Git checkouts where the project is shared. On Windows, check whether Git materializes directory links. A text link stub with core.symlinks=false is not discoverable. Verify a machine-local junction or a managed discovery copy when links cannot be checked out. Treat materialized discovery copies as generated and refresh them from the DIP source after edits. Keep machine-local junctions out of shared Git history. Roll back a group if its discovery, resources or required project checks fail.

4. Refresh DIP with `dip skills sync`. Report the migrated groups, their discovery and canonical paths, verification results, and any groups still pending. Keep changes in the local working trees unless the user requests a commit or push.

For all future external agent skills, use `dip skills create NAME --description TEXT` from the intended project or pass `--root PROJECT`. Add `--scope DIRECTORY` for a nested skill, `--host claude` for Claude Code or `--global` for a user-wide skill. Author SKILL.md and supporting files at the returned canonicalSource, then verify native discovery in a fresh session. Keep new skills consumed by application-internal agents in the application's own structure. Run `dip skills --help` to check command availability. If the installed DIP predates this command, use the verified storage-and-discovery layout above or update from your trusted DIP source. On older installs, record the same rule additively in each project’s trusted AGENTS.md or CLAUDE.md outside DIP-managed blocks. Preserve existing instructions. Refresh owned project guidance with `dip repository --root PROJECT` when the current DIP supports the new authoring policy.
